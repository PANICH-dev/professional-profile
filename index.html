Core Business Rules & System Logic

1. Quota Lock Validation หากยอดคำนวณชิ้นงานซ่อมรายวัน (Main/Sub) เกิน Capacity ที่ตั้งไว้ในระบบ (rizenic_quotas) ระบบจะ Block การบันทึกรับรถเพิ่มทันที เพื่อกัน Overbooking
2. Parts Dependency ระบบล็อคสถานะ ห้ามเปลี่ยนสเตตัสเป็น "กำลังซ่อม" เด็ดขาด หากตารางสั่งอะไหล่ (PO) ยังไม่ระบุสถานะว่า "อะไหล่มาครบแล้ว"
3. Auto-Highest Station เมื่อช่างติ๊ก Checkbox ข้ามสถานี (เช่น ติ๊ก รอส่งมอบ) ระบบจะคำนวณ Reverse Priority และปรับสเตตัสหลักให้ไปอยู่จุดสูงสุดแบบอัตโนมัติ
4. Anti-Backdating มี Logic ล็อคปฏิทิน ไม่อนุญาตให้ผู้ใช้งานใส่วันที่ "เสร็จจริง" หรือวันที่ปิดบิล ย้อนหลังก่อนหน้าปัจจุบัน เพื่อป้องกันการทุจริต KPI

4. Practical SQL

Query ดึงข้อมูลสรุปต้นทุนและระยะเวลาซ่อมเฉลี่ย เพื่อเชื่อมต่อไปยัง BI Dashboard

-- คำนวณจำนวนใบงาน และต้นทุนรวม แยกตามประเภทลูกค้า
SELECT 
  c.customer_type,
  COUNT(j.job_id) AS total_jobs,
  SUM(j.cost_labor + j.cost_parts) AS total_cost,
  ROUND(AVG(j.repair_days), 1) AS avg_days
FROM service_jobs j
JOIN customers c ON j.customer_id = c.customer_id
WHERE j.job_status = 'COMPLETED'
GROUP BY c.customer_type
ORDER BY total_cost DESC;
